# 📡 DNS – Domain Name System (Section 2.4)

---

## 1. DNS là gì?

DNS là **hệ thống tên miền** – một cơ sở dữ liệu phân tán được triển khai theo dạng **phân cấp** trên nhiều name server.

- **Vấn đề**: Máy tính dùng **địa chỉ IP** (32-bit) để định danh, nhưng con người dùng **tên** (vd: `cs.umass.edu`).
- **Giải pháp**: DNS dịch (map) qua lại giữa tên và địa chỉ IP.
- DNS là **giao thức tầng ứng dụng** – phần phức tạp nằm ở "rìa" mạng.

---

## 2. Dịch vụ của DNS

| Dịch vụ | Mô tả |
|---|---|
| **Hostname → IP** | Dịch tên máy chủ ra địa chỉ IP |
| **Host aliasing** | Tên bí danh → tên chính thức (canonical) |
| **Mail server aliasing** | Tìm mail server cho domain |
| **Load distribution** | Nhiều IP ↔ 1 tên (web server nhân rộng) |

---

## 3. Tại sao không tập trung DNS?

❌ **Không thể tập trung vì:**
- Single point of failure (một điểm hỏng = toàn mạng sập)
- Lưu lượng cực lớn (Comcast: 600 tỷ query/ngày; Akamai: 2,2 nghìn tỷ/ngày)
- Cơ sở dữ liệu quá xa người dùng
- Khó bảo trì

✅ **Giải pháp**: Phân tán + phân cấp.

---

## 4. Kiến trúc phân cấp DNS

```
Root DNS Servers
    ├── .com DNS servers
    ├── .org DNS servers
    └── .edu DNS servers
            ├── umass.edu DNS servers
            └── nyu.edu DNS servers
                    └── amazon.com DNS servers ...
```

### Ba cấp chính:

| Cấp | Vai trò |
|---|---|
| **Root name servers** | Tiếp nhận query cuối cùng; 13 server logic (~200 thực tế tại Mỹ); do ICANN quản lý |
| **TLD servers** | Phụ trách `.com`, `.org`, `.edu`, `.vn`, v.v.; vd: Network Solutions quản lý `.com`, `.net` |
| **Authoritative servers** | Server của từng tổ chức; lưu ánh xạ hostname → IP chính thức |

### Local DNS server:
- Không thuộc phân cấp chính thức
- Mỗi ISP có 1 local DNS server
- Nhận query từ host, rồi tra cache hoặc truy vấn lên cấp trên

---

## 5. Hai kiểu phân giải tên

### 🔁 Iterated Query (Truy vấn lặp)
- Server được hỏi **trả lời tên server tiếp theo** cần hỏi.
- Client tự đi hỏi từng bước: local DNS → root → TLD → authoritative.

```
engineering.nyu.edu muốn biết IP của gaia.cs.umass.edu:
1 → 2: hỏi local DNS (dns.nyu.edu)
2 → 3: hỏi root DNS
3 → 4: root trả về địa chỉ TLD (.edu)
4 → 5: hỏi TLD
5 → 6: TLD trả về authoritative (dns.cs.umass.edu)
6 → 7: hỏi authoritative
7 → 8: nhận IP của gaia.cs.umass.edu
```

### 🔄 Recursive Query (Truy vấn đệ quy)
- **Gánh nặng** đặt lên server được hỏi – server đó tự đi hỏi tiếp và trả kết quả cuối.
- Gây tải nặng ở các cấp trên.

---

## 6. DNS Caching

- Khi name server học được một ánh xạ, nó **lưu vào cache** và trả kết quả ngay cho các query sau.
- Cache có **TTL (Time To Live)** – hết hạn thì xóa.
- TLD server thường được local DNS cache → có thể bỏ qua root server.
- ⚠️ Cache có thể **lỗi thời** nếu host đổi IP nhưng TTL chưa hết.

---

## 7. DNS Records (Resource Records – RR)

Định dạng: `(name, value, type, ttl)`

| Type | name | value |
|---|---|---|
| **A** | hostname | địa chỉ IP |
| **NS** | domain (vd: foo.com) | hostname của authoritative server |
| **CNAME** | tên bí danh | tên chính thức (canonical name) |
| **MX** | domain | tên SMTP mail server |

---

## 8. Cấu trúc DNS Message

DNS query và reply **dùng cùng định dạng**:

| Trường | Kích thước |
|---|---|
| Identification | 2 bytes – số ID, reply dùng lại cùng ID |
| Flags | 2 bytes – query/reply, recursion desired/available, authoritative |
| # Questions / Answers / Authority / Additional RRs | biến đổi |

---

## 9. Đưa tên vào DNS

Ví dụ startup "Network Utopia" muốn đăng ký `networkutopia.com`:

1. Đăng ký tên tại **DNS registrar** (vd: Network Solutions).
2. Cung cấp tên + IP của authoritative server (primary & secondary).
3. Registrar thêm vào TLD `.com`:
   - `(networkutopia.com, dns1.networkutopia.com, NS)`
   - `(dns1.networkutopia.com, 212.212.212.1, A)`
4. Tạo authoritative server local với:
   - Bản ghi **A** cho `www.networkutopia.com`
   - Bản ghi **MX** cho `networkutopia.com`

---

## 10. DNS Security

| Tấn công | Mô tả | Phòng chống |
|---|---|---|
| **DDoS vào root** | Làm tê liệt root server | Lọc traffic; local DNS cache TLD → bypass root |
| **DDoS vào TLD** | Nguy hiểm hơn | Khó chống hơn |
| **Spoofing / Cache Poisoning** | Chặn query, trả reply giả | DNSSEC (RFC 4033) – xác thực, toàn vẹn message |

---

> 💡 **Tóm lại**: DNS là xương sống ẩn của Internet – hầu hết mọi giao dịch Internet đều tương tác với DNS. Nó được thiết kế phân tán, phân cấp để đảm bảo hiệu năng, độ tin cậy và khả năng mở rộng.
