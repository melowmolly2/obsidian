# 📚 Phần 2.2 – Web và HTTP

## 1. Tổng quan Web
- **Web page** gồm nhiều **objects** (HTML file, JPEG, audio, applet…), mỗi object có thể lưu trên các server khác nhau.
- Mỗi object được địa chỉ hóa bằng **URL** gồm: *hostname* + *path name*.

---

## 2. HTTP (HyperText Transfer Protocol)

- Là giao thức **application-layer** của Web.
- Mô hình **client/server**: trình duyệt (client) gửi HTTP request → server trả HTTP response.
- HTTP dùng **TCP** (port 80): client khởi tạo kết nối TCP → server chấp nhận → trao đổi message → đóng kết nối.
- HTTP là **stateless** (phi trạng thái): server không lưu thông tin về các request trước.

---

## 3. Hai loại HTTP connection

| | Non-persistent HTTP | Persistent HTTP (HTTP 1.1) |
|---|---|---|
| Kết nối TCP | Mở/đóng mỗi object | Mở một lần, dùng cho nhiều object |
| RTT cần | 2 RTT/object | ~1 RTT cho tất cả objects |
| Nhược điểm | Tốn tài nguyên OS, nhiều RTT | — |

**Thời gian phản hồi Non-persistent:**

$$
\text{Response time} = 2 \times RTT + \text{file transmission time}
$$

---

## 4. HTTP Request Message

- Định dạng **ASCII** (con người đọc được).
- Dòng đầu: **request line** → `Method URL Version`
- Các method chính:
  - **GET** – lấy object (có thể gửi data qua URL: `?key=value`)
  - **POST** – gửi dữ liệu form trong entity body
  - **HEAD** – chỉ lấy header (không lấy object)
  - **PUT** – upload/thay thế file lên server

---

## 5. HTTP Response Message

- **Status line**: protocol + status code + phrase
- Các status code quan trọng:

| Code | Ý nghĩa |
|---|---|
| 200 OK | Thành công |
| 301 Moved Permanently | Object đã chuyển chỗ |
| 400 Bad Request | Request không hợp lệ |
| 404 Not Found | Không tìm thấy |
| 505 HTTP Version Not Supported | Phiên bản không hỗ trợ |

---

## 6. Cookies – Duy trì trạng thái

Vì HTTP stateless, **cookies** được dùng để lưu trạng thái:

4 thành phần:
1. Header `Set-cookie` trong HTTP response
2. Header `Cookie` trong HTTP request tiếp theo
3. File cookie lưu trên máy client (quản lý bởi browser)
4. Cơ sở dữ liệu phía server

**Ứng dụng:** xác thực, giỏ hàng, gợi ý, session e-mail.
**Vấn đề privacy:** cookie bên thứ 3 (tracking cookies) theo dõi người dùng qua nhiều trang web.

---

## 7. Web Cache (Proxy Server)

- **Mục tiêu:** phục vụ request mà không cần liên hệ origin server.
- Cache vừa đóng vai trò **server** (với client) vừa là **client** (với origin server).
- **Lợi ích:**
  - Giảm thời gian phản hồi (cache gần client hơn)
  - Giảm traffic trên đường truyền

### Ví dụ tính toán (Caching example):

**Kịch bản gốc (không cache):**
- Access link: 1.54 Mbps, data rate: 1.50 Mbps
- Utilization access link = **0.97** → delay **hàng phút**!

**Phương án 1:** Nâng cấp link lên 154 Mbps → utilization = 0.0097 → delay msecs → **đắt tiền**.

**Phương án 2:** Cài Web cache (hit rate = 0.4):

$$
\text{Access link utilization} = \frac{0.6 \times 1.50}{1.54} \approx 0.58
$$

$$
\text{Average end-end delay} = 0.6 \times 2.01 + 0.4 \times (\approx 0) \approx 1.2 \text{ sec}
$$

→ **Rẻ hơn** và **delay thấp hơn** cả phương án mua link nhanh!

---

## 8. Conditional GET

- **Mục tiêu:** không gửi object nếu cache đã có bản mới nhất.
- Client thêm header: `If-modified-since: <date>`
- Server trả lời:
  - `304 Not Modified` → không gửi object (tiết kiệm băng thông)
  - `200 OK <data>` → gửi object mới

---

## 9. HTTP/2

**HTTP 1.1 vấn đề:**
- FCFS (First-Come-First-Served): object nhỏ phải chờ sau object lớn → **Head-of-Line (HOL) blocking**

**HTTP/2 cải tiến:**
- Gửi object theo **thứ tự ưu tiên** do client chỉ định (không nhất thiết FCFS)
- **Push** object chưa được yêu cầu đến client
- Chia object thành **frames**, lên lịch frames để giảm HOL blocking

---

## 🔑 Tóm tắt các điểm mấu chốt

| Khái niệm | Nội dung cốt lõi |
|---|---|
| HTTP | Stateless, dùng TCP, port 80 |
| Non-persistent | 2RTT/object, tốn kém |
| Persistent | ~1RTT cho nhiều object |
| Cookies | Thêm trạng thái vào HTTP stateless |
| Web Cache | Giảm delay & traffic, rẻ hơn nâng cấp link |
| Conditional GET | `304 Not Modified` → không truyền thừa |
| HTTP/2 | Ưu tiên linh hoạt, frame-based, tránh HOL blocking |
