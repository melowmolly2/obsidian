### Khái niệm cơ bản

- **Multiplexing (tại sender):** Gom dữ liệu từ **nhiều socket**, thêm transport header → gửi xuống.
- **Demultiplexing (tại receiver):** Dùng thông tin header để chuyển segment đến **đúng socket**.

---

### Cách demultiplexing hoạt động

Host nhận IP datagram, mỗi datagram chứa:
- **Source IP / Dest IP**
- **Source port / Dest port**

Host dùng **IP + port** để định tuyến segment tới socket đúng.

**Cấu trúc segment TCP/UDP:**

$$
\underbrace{\text{source port \#}}_{\text{16 bits}} \quad \underbrace{\text{dest port \#}}_{\text{16 bits}} \quad \underbrace{\text{other fields + payload}}{}
$$

---

### UDP – Connectionless Demultiplexing

- Socket tạo bằng cách chỉ định **port cục bộ** (vd: `DatagramSocket(12534)`)
- Nhận segment → kiểm tra **dest port** → chuyển đến socket có port đó
- Gởi datagram cần: **dest IP + dest port**
- **Nhiều datagram** cùng dest port → cùng một socket, dù source IP/port khác nhau

> **UDP demux dựa trên: dest port số (chỉ 1 trường)**

---

### TCP – Connection-Oriented Demultiplexing

- TCP socket được xác định bởi **4-tuple:**

$$
(\text{Source IP},\ \text{Source Port},\ \text{Dest IP},\ \text{Dest Port})
$$

- Server có thể có **nhiều socket TCP đồng thời**, mỗi socket phục vụ 1 client khác nhau
- Receiver dùng **cả 4 giá trị** để định tuyến segment

**Ví dụ:**

| Segment | Source | Dest |
|---|---|---|
| 1 | A:9157 | B:80 |
| 2 | C:5775 | B:80 |
| 3 | C:9157 | B:80 |

→ Tuy cùng dest **B:80**, 3 segment được demux tới **3 socket khác nhau** vì source khác.

> **TCP demux dựa trên: 4-tuple (source IP, source port, dest IP, dest port)**

---

### Tóm tắt

| | UDP | TCP |
|---|---|---|
| Demux dựa trên | Dest port (2 trường) | 4-tuple |
| Số socket/connection | 1 socket ← nhiều client | 1 socket / 1 client |
| Loại | Connectionless | Connection-oriented |

> Multiplexing/Demultiplexing xảy ra **ở mọi tầng** trong mô hình mạng.
