### 1. Đặc điểm TCP
- **Point-to-point**: 1 sender, 1 receiver
- **Reliable, in-order byte stream**: không có "message boundaries"
- **Full duplex**: dữ liệu 2 chiều trong cùng 1 kết nối
- **Connection-oriented**: handshake trước khi trao đổi dữ liệu
- **Flow controlled**: sender không làm tràn buffer receiver
- **Pipelining** với **cumulative ACKs**
- **MSS** (Maximum Segment Size) điển hình: **1460 bytes**

---

### 2. Cấu trúc TCP Segment
Các trường quan trọng:

| Trường | Ý nghĩa |
|---|---|
| Sequence number | Số byte đầu tiên trong segment |
| Acknowledgement number | Seq # byte tiếp theo mong đợi (cumulative ACK) |
| Receive window (rwnd) | Flow control: số byte receiver sẵn sàng nhận |
| Flags: SYN, FIN, RST, ACK | Quản lý kết nối |
| Flags: C, E | Congestion notification |
| Checksum | Internet checksum |

---

### 3. RTT và Timeout

$$\text{EstimatedRTT} = (1-\alpha)\cdot\text{EstimatedRTT} + \alpha\cdot\text{SampleRTT}$$

$$\text{DevRTT} = (1-\beta)\cdot\text{DevRTT} + \beta\cdot|\text{SampleRTT} - \text{EstimatedRTT}|$$

$$\text{TimeoutInterval} = \text{EstimatedRTT} + 4\cdot\text{DevRTT}$$

- Typical: $\alpha = 0.125$, $\beta = 0.25$
- EWMA (Exponential Weighted Moving Average)

---

### 4. TCP Sender & Receiver

**Sender** xử lý 3 sự kiện:
1. **Data từ app** → tạo segment, gán seq#, start timer (nếu chưa chạy)
2. **Timeout** → retransmit segment gây timeout, restart timer
3. **ACK nhận được** → cập nhật ACKed data, start timer nếu còn unACKed

**Receiver** — ACK generation:

| Sự kiện | Hành động |
|---|---|
| Segment đúng thứ tự, chưa có pending ACK | Delayed ACK (chờ max 500ms) |
| Segment đúng thứ tự, có 1 pending ACK | Gửi 1 cumulative ACK cho cả 2 |
| Segment out-of-order (gap detected) | Gửi ngay duplicate ACK |
| Segment lấp đầy gap | Gửi ngay ACK |

---

### 5. Retransmission Scenarios
- **Lost ACK**: timeout → retransmit
- **Premature timeout**: segment retransmit nhưng receiver dùng cumulative ACK
- **Cumulative ACK bù cho ACK bị mất**: ACK sau bao phủ luôn segment trước

---

### 6. TCP Fast Retransmit
> Nhận **3 duplicate ACKs** → retransmit ngay segment cũ nhất chưa ACKed, **không chờ timeout**

---

### 7. Flow Control
- Receiver **quảng bá** free buffer qua trường `rwnd` trong TCP header
- Sender giới hạn dữ liệu in-flight ≤ `rwnd`
- Mặc định `RcvBuffer` = 4096 bytes (OS có thể tự điều chỉnh)

---

### 8. Connection Management – 3-way Handshake

**Vấn đề 2-way handshake**: có thể tạo half-open connection hoặc chấp nhận data từ kết nối cũ đã chết.

**Giải pháp: 3-way handshake**
1. Client → SYN (SYNbit=1, Seq=x)
2. Server → SYNACK (SYNbit=1, Seq=y, ACKnum=x+1)
3. Client → ACK (ACKnum=y+1) → cả 2 vào trạng thái **ESTAB**

Trạng thái: `LISTEN → SYN SENT/SYN RCVD → ESTAB`
