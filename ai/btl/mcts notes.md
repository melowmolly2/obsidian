In this video, I'm going to give a brief overview of the Monte Carlo tree search—or MCTS—algorithm, how it operates in the general sense, as well as why it's now utilized in a variety of problem spaces, such as video game AI opponents and expert computer players in video games.

MCTS is a heuristic-driven search algorithm that combines classic tree search implementations with the machine learning principles of reinforcement learning. Tree search algorithms connect the potential states of a given problem by the actions that will achieve them. We then write algorithms that can search within this space to make intelligent decisions that yield a desired outcome by exploring the tree to find a goal state. The simplest versions of these are uninformed algorithms, such as breadth-first and depth-first search, which follow very strict and specific orderings of states to visit. More intelligent algorithms, such as A*, use metrics like the cost of an action alongside a heuristic that estimates the value of a state in solving a problem.

Meanwhile, reinforcement learning is a branch of machine learning that learns good strategies for the problem it's trying to solve. It aims to achieve an optimal strategy by repeatedly using the best actions it has found so far. However, there's always the possibility that the current best action is not actually optimal. As such, it will continue to evaluate alternatives periodically during the learning phase by executing them instead of the perceived optimal choice. This is known in reinforcement learning as the exploration-exploitation trade-off: it will exploit the actions and strategies it has found to be the best, but it must also continue to explore the local space of alternative decisions to see whether they could replace the current best. This is a difficult process to resolve, given that sometimes we need to explore a series of decisions to discover that an action that looks bad now will actually prove to be a great idea somewhere down the line. The perceived value of these actions and their subsequent states is encoded into the state space itself, with the value of a state being continually updated and improved the more the algorithm tries the options available to it and learns whether they were good decisions or not.

MCTS essentially merges these two practices together. It uses a tree model of the world that it searches for the best possible path by exploring specific subsections of the tree, calculating how effective they were, and then updating the value of states within it based on the outcome. By doing this hundreds—if not thousands—of times, it can establish the best path to take through the tree and give the best answer to a given problem. This repeated evaluation to determine the value of a state or strategy is derived from the Monte Carlo method, a type of algorithm that repeatedly samples a problem space randomly in order to obtain a more accurate understanding of the best answers within it.

It carries many similarities to an existing tree search algorithm called minimax, which also evaluates the options of a tree to make a decision. The problem with minimax occurs in large problem spaces where an agent can execute a vast number of actions, which dramatically increases the number of states on the next layer down in the tree that the algorithm has to explore. This property is known as the branching factor. If the branching factor is high, algorithms like minimax don't scale well at all, given they need to evaluate every opportunity quite thoroughly, making adapted versions such as alpha-beta pruning a requirement to explore large and complex problems.

This is where MCTS proves its value. It only searches a couple of layers deep into the tree, prioritizes which parts of the tree to explore, simulates the outcome rather than exhaustively expanding the search space, and can be limited in how many evaluations it makes. This helps with problems that have a very high branching factor, as it isolates which parts of the tree it should explore.

The individual evaluations rely on the use of a "playout," where the algorithm effectively plays the game from a given starting point all the way to the end by making random decisions—a concept derived from the Monte Carlo method. Exploring the future states of a game can be difficult depending on the game itself; board games are often easier to encode and allow time to run evaluations, whereas large-scale, real-time video games make this much more difficult. As such, MCTS uses what's called a forward model: an abstract approximation of the game logic that allows it to consider the outcome of playing action $X$ in state $Y$, resulting in outcome $Z$. It runs a playout to a terminal state and then records the result, which is used to update the value of a given state in the tree. Once it's done running evaluations, it simply selects the action that had the best rollout score.

The smart part comes in how each rollout is decided upon and executed. To do this, it relies on four key steps: **selection**, **expansion**, **simulation**, and **backpropagation**.

1. **Selection** takes the current state of the tree and selects decisions down that tree to a future state at a fixed depth.
    
2. **Expansion** then moves one step down to expose a new state in the tree, provided the state reached didn't end the game (either as a win or a loss) or exceed the tree depth.
    
3. **Simulation** evaluates the value of that state. It is the random playout phase that plays a game of completely random decisions from this point until it reaches either a terminal state (where it wins or loses) or a simulation cap. It then returns a score indicating how well it performed.
    
4. **Backpropagation** takes that score and updates the perceived value of not just the state where the rollout ran, but every state that led to it in the tree. Any score, whether positive or negative, propagates back up the tree to the starting point.
    

Through these four phases, we can take decisions to a fixed point in the tree, simulate their outcome, and propagate back the perceived value. Doing this once isn't enough—you have to do it hundreds or thousands of times and balance which playouts to make. Once the playout limit is reached, the algorithm is done and takes the action leading to the highest-value state.

Different MCTS algorithms balance the playouts so that they shift focus to different parts of the tree periodically, ensuring there are no better solutions to be found that they didn't otherwise spot. The original implementation of this balancing act is UCT, or Upper Confidence Bound 1 applied to trees. UCT chooses which node to visit next based on an equation where the left-hand side ensures we retain some aspect of history in our decision-making—this is the exploitation part of the algorithm. Meanwhile, the remaining terms act as the exploration component, meaning it will periodically encourage exploring other parts of the space as the number of evaluations increases.

What makes the system even more powerful is that it's what we call an "anytime algorithm," meaning it will always give an answer regardless of how many playouts we let it make. In a context like a video game where CPU and memory resources are tight, if it needs to stop evaluating the game at a moment's notice, it will still give the best answer it could within that time. Despite this, giving it a massive amount of CPU resources won't necessarily result in god-like AI, given that the knowledge accrued from repeatedly running playouts may eventually level off.

MCTS is proving very popular in areas of general intelligence and expert play—most notably as part of the action selection process in the expert Go player AlphaGo by Google DeepMind, as well as in the video game industry. To date, the most notable examples of its adoption include the sadly canceled _Fable Legends_ alongside the _Total War_ franchise (a point I discuss at length in parts three and four of my _AI of Total War_ series). It's also being used in research in areas such as _Ms. Pac-Man_, _Magic: The Gathering_, and general intelligence as part of the General Video Game AI competition.
