- Code smells are usually not bugs
- Identify design deficeincies that negatively impact development speed and elevate the risk of bugs or system failures
- Kind of code smells
	- Condition & Parameter
	- Method
	- Field
	- Class/interface
## Refactoring
- Refactoring (noun): a change made to the internal structure of software to make it easier to understand and cheaper to modify without changing its observable behavior

# Method refactoring
## Extract Method
- Problem: You have a code fragment that can be grouped together
- Why Refactor: The more lines found in a method, the harder it is to figure out what the method does
- Solution
	- Move this code to a seperate new method (or function) 
	- Replace the old code with a call to the method
![](../Assets/Pasted%20image%2020260529211919.png)
## Inline method
- Problem: a method body is more obvious than the method itself
- Solution: Replace calls to the method with the method itself 
- Benefit: By minimzing the number of unneeded methods, you make the code more straightforward.
![](../Assets/Pasted%20image%2020260529212103.png)

## Pull up method
- Problem: Your subclasses have methods that perform similar work
- Solution: Make the methods identical and then move them to the relevant superclass
- Why Refactor: Subclasses grew and developed independently of one another, causing identical (or nearly identical) fields and methods
![](../Assets/Pasted%20image%2020260529212337.png)
## Replace method with method objects
- Problem: You have a long method
- Solution:
	- Transform the method into a seperate class so that the local variables become fields of the class
	- Then you can split the method into several methods within the same class
- Drawback: Another class is added, increasing the overall complexity of the program
-![](../Assets/Pasted%20image%2020260529212455.png)
# Field refactoring
## Move Field
- Problem: A field is used more in another class than in its own class
- Solution: Create a field to a new class and redirect all users of the old field to it
![](../Assets/Pasted%20image%2020260529212607.png)
## Replace magic number with constant
- Problem: Your code uses a number that has a certain meaning to it
- Solution: Replace this number with a constant that has a human-readable name explaining the meaning of the number

# Class/interface refactoring
## Extract Class
- Problem: When one class does the work of two, awkwardness results (violate Single Responsibility Principle)
- Solution: Instead, create a new class and place the fields and methods responsible for the relevant functionality in it
## Replace conditional with polymorphism
- Problem: You have a conditional that performs various actions depending on object type or properties
- Solution: Create subclasses matching the branches of the conditional
![](../Assets/Pasted%20image%2020260530074630.png)
![](../Assets/Pasted%20image%2020260530074654.png)
## Extract superclass
- Problem: You have two classes with common fields and methods
- Solution: Create a shared superclass for them and move all the identical fields and methods to it
![](../Assets/Pasted%20image%2020260530074754.png)
![](../Assets/Pasted%20image%2020260530074807.png)
## Extract interface
- Problem
	- Multiple clients are using the same part of a class interface
	- Another case: part of the interface in two classes is the same
- Solution
	- Move this identical portion to its own interface
	- ![](../Assets/Pasted%20image%2020260530074934.png)
## Extract subclass
- Problem: A class has features that are used only in certain cases
- Solution: Create a subclass and use it in these cases
