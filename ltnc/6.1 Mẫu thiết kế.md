---

## 1. Tổng quan

- MTK = giải pháp đã được kiểm chứng cho các vấn đề lặp lại trong phần mềm (best practice)
- Mốc: **1995** — *Gang of Four* (Gamma, Helm, Johnson, Vlissides) — cuốn *Design Patterns: Elements of Reusable Object-Oriented Software*
- Giải quyết vấn đề **phi chức năng**: khả năng thay đổi, tương tác, tái sử dụng, độ tin cậy

**3 loại MTK:**

| Loại | Mô tả |
|---|---|
| **Khởi tạo** (Creational) | Liên quan đến tạo đối tượng |
| **Cấu trúc** (Structural) | Tổ chức lớp và đối tượng |
| **Hành vi** (Behavioral) | Gán chức năng cho lớp |

**Nội dung một MTK gồm:** Tên · Ngữ cảnh · Vấn đề · Giải pháp · Kết quả

## 2. Singleton *(Creational)*

**Code smell:** Global Data / Mutable State — nhiều instance gây race condition.

**Mục tiêu:** Đảm bảo **chỉ 1 đối tượng** của lớp được tạo ra.

**Giải pháp:**
- Constructor là `private`
- Phương thức `getInstance()` kiểm tra nếu chưa có instance → tạo mới; ngược lại trả về instance cũ

```java
class Singleton {
    private static Singleton instance = null;
    private Singleton() {}
    public static Singleton getInstance() {
        if (instance == null)
            instance = new Singleton();
        return instance;
    }
}
```

**Dùng khi:** Kết nối DB, Window manager, File system, …

**Thảo luận:** Đa luồng → cần `synchronized`; kế thừa Singleton → phức tạp.

## 3. Factory Method *(Creational)*

**Code smell:** Conditional Complexity — `if-else`/`switch` khổng lồ để quyết định tạo lớp nào.

**Ngữ cảnh:** Framework có `Application` (trừu tượng) tạo `Document` (trừu tượng). `Application` không biết lớp con cụ thể của `Document`.

**Giải pháp:** Định nghĩa interface tạo đối tượng, **để lớp con quyết định** lớp nào thực sự được tạo.

```
Application (abstract)           Document (abstract)
  +createDocument(): Document      +open(), close(), save()
       ↑                                  ↑
MyApplication                       MyDocument
  +createDocument()
     → return new MyDocument()
```

**Luồng hoạt động:**
```java
// trong Application.newDocument()
Document doc = createDocument();   // gọi factory method
docs.add(doc);
doc.open();
```

## 4. Abstract Factory *(Creational)*

**Code smell:** Combinatorial Explosion — nhiều họ đối tượng (Windows vs Mac buttons/scrollbars), code lộn xộn kiểm tra trộn lẫn.

**Ngữ cảnh:**
- Client độc lập với cách tạo đối tượng
- Tại mỗi thời điểm chỉ dùng **một "dòng" (family)** đối tượng
- Các đối tượng cùng dòng dùng cùng nhau

**Giải pháp:** Factory trừu tượng định nghĩa interface tạo nhiều loại product; mỗi Concrete Factory tạo một họ cụ thể.

**Thảo luận:** Thêm product type → phải sửa tất cả factory → khó mở rộng; thường kết hợp Singleton cho factory.

## 5. Adapter *(Structural)*

**Code smell:** Incompatible Interfaces — thư viện tốt nhưng "hình dạng" không khớp hệ thống.

**Ngữ cảnh:**
- Framework `F` yêu cầu interface `IMath` có `sort(int[])`
- Có sẵn `MyMathLib` với `quickSort(int[])` (không sửa được)

**Giải pháp:** Tạo lớp **Adapter** implement `IMath`, bên trong bọc `MyMathLib`:

```java
// Object Adapter
public int[] sort(int[] arr) {
    MyMathLib lib = new MyMathLib();
    return lib.quickSort(arr);
}
```

Hai dạng:
- **Class Adapter** — kế thừa Adaptee (`extends MyMathLib`)
- **Object Adapter** — giữ tham chiếu Adaptee (linh hoạt hơn)

## Tổng kết nhanh

| Pattern | Loại | Giải quyết |
|---|---|---|
| Singleton | Creational | Chỉ 1 instance |
| Factory Method | Creational | Lớp con quyết định tạo gì |
| Abstract Factory | Creational | Họ đối tượng nhất quán |
| Adapter | Structural | Kết nối interface không tương thích |
