---

## 1. Lớp trừu tượng (`abstract class`)

- Không thể tạo đối tượng trực tiếp từ lớp trừu tượng.
- Dùng làm khuôn mẫu cho các lớp dẫn xuất kế thừa.
- Quan hệ **"is-a"** (Dog *is-a* Animal, Circle *is-a* Shape).

```java
abstract class Shape {
    protected int x, y;
    abstract public void draw();   // abstract method
    abstract public void erase();
    public void moveTo(int x1, int y1) { ... } // method thường
}

Shape s = new Shape(10, 10);  // compile error!
Shape s1 = new Circle();      // OK - đa hình
```

**Quy tắc:**
- Lớp chứa ít nhất 1 abstract method → phải khai báo `abstract`.
- Lớp dẫn xuất **bắt buộc** override tất cả abstract method, hoặc tự khai báo `abstract`.

---

## 2. Giao diện (`interface`)

- Mức trừu tượng cao hơn abstract class.
- Chứa: abstract method (mặc định `public`) + hằng số (`public static final`).
- Dùng với quan hệ **"behaves-like"** (can fight, can swim, can fly...).

```java
interface Action {
    void moveTo(int x, int y);
    void erase();
    void draw();
}

class Circle implements Action { ... }
abstract class Shape implements Action { ... }

// Interface kế thừa interface (đa kế thừa)
interface I3 extends I1, I2 { ... }

// Class implement nhiều interface
class Hero extends ActionCharacter implements CanFight, CanSwim, CanFly { ... }
```

**So sánh abstract class vs interface:**

| | Abstract class | Interface |
|---|---|---|
| Quan hệ | is-a | behaves-like |
| Đa kế thừa | Không | Có |
| Hằng số | Không bắt buộc | `public static final` |
| Method thường | Có | Không (Java < 8) |

## 3. Lập trình tổng quát (Generics)

Khi định nghĩa lớp/giao diện/phương thức, **không cần xác định kiểu cụ thể**; khi dùng mới xác định.

### 3.1 Lớp tổng quát

```java
public class Box<T> {
    private T t;
    public void set(T t) { this.t = t; }
    public T get() { return t; }
}

Box<Integer> box = new Box<Integer>();

public class Pair<K, V> {
    private K key;
    private V value;
}
Pair<String, Integer> p = new Pair<>("Even", 8);
```

**Quy ước tên:** `E` (Element), `K`/`V` (Key/Value), `N` (Number), `T` (Type).

**Thừa kế lớp tổng quát:**
```java
class ContactEntry extends Pair<String, Integer> { }       // cố định cả hai
class ContactEntry<V> extends Pair<String, V> { }          // cố định một
class ContactEntry<K, V> extends Pair<K, V> { }            // giữ nguyên
class ContactEntry<K, V, T> extends Pair<K, V> { }         // thêm tham số
```

### 3.2 Giao diện tổng quát

```java
public interface GenericDao<T> {
    void insert(T obj);
    void update(T obj);
}
public abstract class AbstractGenericDao<T> implements GenericDao<T> {}
```

### 3.3 Phương thức tổng quát

```java
public static <K, V> boolean compare(Pair<K, V> p1, Pair<K, V> p2) {
    return p1.getKey().equals(p2.getKey()) && p1.getValue().equals(p2.getValue());
}
```

### 3.4 Khởi tạo kiểu tổng quát

**Không thể** dùng `new T()` hay `new T[5]` trực tiếp → dùng **Reflection**:
```java
Class.forName("TenLop").newInstance();  // tạo object từ tên lớp dạng String
```

### 3.5 Wildcard (`?`)

| Ký hiệu | Ý nghĩa |
|---|---|
| `<?>` | Chấp nhận mọi kiểu |
| `<? extends T>` | T hoặc con của T (upper bound) |
| `<? super T>` | T hoặc cha của T (lower bound) |

```java
List<?>              // OK
List<? extends Number>  // OK
// Không thể new đối tượng kiểu wildcard
```

### 3.6 Ưu/nhược điểm Generics

**Ưu:** Giảm code trùng lặp, phát hiện lỗi kiểu tại compile-time, tái sử dụng cao.  
**Nhược:** Không thể dùng kiểu nguyên thủy (`int`, `double`...), không tạo trực tiếp instance kiểu tổng quát.
