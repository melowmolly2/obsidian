# 📘 Lý thuyết tuần 5.2: Xử lý Ngoại lệ & Luồng Vào/Ra (Java)

---

## I. XỬ LÝ NGOẠI LỆ

### 1. Ngoại lệ là gì?
Ngoại lệ (Exception) là một sự kiện xảy ra khi thực thi chương trình, **phá vỡ luồng hoạt động mong đợi**.

---

### 2. Ba loại ngoại lệ

| Loại | Tên | Mô tả |
|---|---|---|
| 1 | **Checked Exception** | Chương trình **có thể dự đoán và xử lý** được. Là tất cả exception trừ Error và RuntimeException. |
| 2 | **Runtime Exception** | **Unchecked exception.** Chương trình không thể dự đoán. Nguyên nhân từ bug lập trình (sai API, sai logic). |
| 3 | **Error** | **Unchecked.** Lỗi ngoài tầm kiểm soát (phần cứng, hệ thống). Ví dụ: `OutOfMemoryError`, `IOError`. |

**Ví dụ:**
- `FileNotFoundException` → checked exception (mở file không tồn tại)
- `NullPointerException` → runtime exception (`null.toString()`)
- `IOError` → lỗi phần cứng khi đọc file

---

### 3. Hai cách xử lý ngoại lệ

- **Cách 1 (truyền thống):** Viết trực tiếp mã xử lý vào thuật toán → **không nên dùng** vì:
  - Logic bị rối, khó đọc
  - Không thể truyền ngoại lệ sang phương thức khác
  - Dễ nhầm lẫn, hay quên xử lý
- **Cách 2 (khuyến nghị):** Dùng `try-catch` / `try-catch-finally` → **tách biệt** xử lý lỗi khỏi thuật toán chính

---

### 4. Cú pháp `try-catch-finally`

```java
try {
    // Mã thuật toán (có thể phát sinh ngoại lệ)
} catch (ExceptionType1 e) {
    // Xử lý nếu xảy ra ExceptionType1
} catch (ExceptionType2 e) {
    // Xử lý nếu xảy ra ExceptionType2
} finally {
    // Luôn chạy dù có ngoại lệ hay không (dùng để giải phóng tài nguyên)
}
```

---

### 5. Kế thừa và ngoại lệ (Override)

Khi override phương thức, phương thức con phải tuân quy tắc về `throws`:
- **Quy tắc 1:** Có thể bỏ throws, hoặc khai báo **cùng hoặc con** của exception lớp cha
- **Quy tắc 2.1:** Có thể thêm **unchecked exception** bất kỳ
- **Vi phạm:** Không được khai báo exception **rộng hơn** (cha của exception lớp cha)

```java
class A {
    public void methodA() throws IOException {}
}
class B extends A {
    public void methodA() throws ArithmeticException {} // ✅ unchecked
}
class C extends B {
    public void methodA() throws Exception {} // ❌ Exception rộng hơn
}
class D extends B {
    public void methodA() {}  // ✅ bỏ throws hoàn toàn
}
```

---

### 6. Hoán đổi Checked → Unchecked Exception

Khi chưa biết xử lý thế nào, có thể bọc checked exception thành `RuntimeException`:

```java
void wrapException() {
    try {
        throw new IOException();
    } catch (IOException e) {
        throw new RuntimeException(e); // bọc thành unchecked
    }
}
```

---

### 7. Tự định nghĩa ngoại lệ

Tạo lớp ngoại lệ riêng bằng cách **kế thừa từ `Exception`**:

```java
class MyException extends Exception {
    public MyException() {}
    public MyException(String msg) {
        super(msg);
    }
}
```

## II. LUỒNG VÀO/RA (I/O Streams)

### 1. Khái niệm

- **Luồng (Stream):** Chuỗi dữ liệu chảy từ nguồn đến đích
- **Bộ đệm (Buffer):** Kỹ thuật tăng hiệu quả I/O — ghi/đọc theo **khối**, giảm số lần tương tác thiết bị. Dùng `flush()` để ghi ngay.

---

### 2. Console I/O

| Đối tượng | Lớp | Chức năng |
|---|---|---|
| `System.out` | `PrintStream` | In ra màn hình |
| `System.err` | `PrintStream` | In thông báo lỗi |
| `System.in` | `InputStream` | Đọc từ bàn phím |

**Đọc từ bàn phím (khuyến nghị):**
```java
InputStreamReader reader = new InputStreamReader(System.in);
BufferedReader in = new BufferedReader(reader);
String s = in.readLine(); // đọc một dòng
```

---

### 3. Lớp `File` (`java.io`)

Dùng để thao tác với tệp và thư mục:

```java
File myFile = new File("data.txt");
File myFile = new File("myDocs", "data.txt");
File myDir  = new File("myDocs");
```

**Các phương thức hay dùng:**

| Nhóm | Phương thức |
|---|---|
| Tên/đường dẫn | `getName()`, `getPath()`, `getAbsolutePath()` |
| Kiểm tra | `exists()`, `canRead()`, `canWrite()`, `isFile()`, `isDirectory()` |
| Thông tin | `length()`, `lastModified()`, `delete()` |
| Thư mục | `mkdir()`, `list()` |

---

### 4. Tệp ký tự (Text File)

**Đọc:**
```java
FileReader reader = new FileReader(new File("data.txt"));
BufferedReader in = new BufferedReader(reader);
String s = in.readLine();
```

**Ghi:**
```java
FileWriter writer = new FileWriter(new File("data.out"));
PrintWriter out = new PrintWriter(writer);
out.println("Hello");
out.close();
```

---

### 5. Tệp dữ liệu nhị phân (Binary/Sequential)

| Mục đích | Lớp |
|---|---|
| Đọc byte từ file | `FileInputStream` |
| Đọc kiểu nguyên thủy | `DataInputStream` |
| Đọc đối tượng | `ObjectInputStream` |
| Ghi byte ra file | `FileOutputStream` |
| Ghi kiểu nguyên thủy | `DataOutputStream` |
| Ghi đối tượng | `ObjectOutputStream` |

**Ví dụ ghi/đọc số nguyên:**
```java
// Ghi
DataOutputStream dout = new DataOutputStream(new FileOutputStream("file.bin"));
dout.writeInt(42);

// Đọc
DataInputStream din = new DataInputStream(new FileInputStream("file.bin"));
int x = din.readInt();
```

---

### 6. Serialization (Chuỗi hóa đối tượng)

Để ghi/đọc đối tượng, lớp phải **implements `Serializable`**:

```java
class Record implements Serializable {
    private String name;
    private float score;
    // ...
}

// Ghi
ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream("file.obj"));
out.writeObject(new Record("john", 5.0f));

// Đọc
ObjectInputStream in = new ObjectInputStream(new FileInputStream("file.obj"));
Record r = (Record) in.readObject();
```

---

### 7. `RandomAccessFile` (Truy cập ngẫu nhiên)

- Đọc/ghi ở **vị trí bất kỳ** trong file (dùng `seek(position)`)
- Kích thước bản ghi phải **cố định**

```java
RandomAccessFile raf = new RandomAccessFile(new File("file.bin"), "rw");
raf.seek(i * 4);     // nhảy đến byte thứ i*4
raf.writeInt(value);
```

---

### 8. Lớp `Scanner` (Java 1.5+)

Hỗ trợ nhập dữ liệu linh hoạt từ nhiều nguồn:

```java
Scanner sc = new Scanner(System.in);       // từ bàn phím
Scanner sc = new Scanner(new File("f.txt")); // từ file
Scanner sc = new Scanner("2 3 5 7");        // từ chuỗi

int i = sc.nextInt();
while (sc.hasNextLong()) sc.nextLong();
```

---

> **Tóm tắt nhanh:** Checked exception phải xử lý hoặc khai báo `throws`. Runtime exception và Error thì không bắt buộc. Dùng `try-catch-finally` để tách biệt logic và xử lý lỗi. Với I/O, bọc luồng cơ bản trong luồng có bộ đệm (`Buffered*`) để tăng hiệu năng.
