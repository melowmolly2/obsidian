### 1. Mẫu Composite

**Vấn đề:** Quản lý hệ thống file gồm `File`, `Shortcut`, `Folder` (folder lồng nhau). Code đầy `instanceof` / `if-else` để phân biệt lá & nút gốc → *code smell: Distinguishing Between Leaves and Containers*.

**Giải pháp — Composite:** Thống nhất tất cả thành phần qua 1 interface chung.

```
print() {
    // Folder
    print(name);
    for o in items:
        o.print();       // gọi đệ quy, không cần instanceof

    // File
    System.out.print(name);
}
```

**Ý tưởng cốt lõi:** Client xử lý lá (File) và nút (Folder) giống hệt nhau thông qua interface chung → xoá bỏ `instanceof`.

### 2. Mẫu Decorator

**Vấn đề:** `Notifier` gửi email. Muốn thêm SMS/Slack/Facebook → tạo subclass cho từng kênh → muốn kết hợp nhiều kênh thì số lớp bùng nổ → *code smell: Subclassing Overload*.

**Giải pháp — Decorator:** Bọc (wrap) object bên trong object khác cùng interface.

```java
// Cấu trúc class
<<Interface>> Notifier { send() }
EmailNotifier implements Notifier
NotifierDecorator implements Notifier {
    Notifier component;          // wrap object
    send() { component.send(); } // ủy quyền
}
SMSNotifier extends NotifierDecorator { notifySMS(); }
FacebookNotifier extends NotifierDecorator { notifyFB(); }

// Sử dụng (main)
Notifier n = new EmailNotifier();
n = new FacebookNotifier(n);   // bọc email
n = new SMSNotifier(n);        // bọc facebook+email
n.send(); // gọi cả 3 kênh theo chuỗi
```

**Cấu trúc tổng quát:**

```
Component (interface) → operation()
  ├── ConcreteComponent
  └── Decorator (giữ component)
        ├── ConcreteDecoratorA
        ├── ConcreteDecoratorB
        └── ConcreteDecoratorC
```

### 3. Proxy (đề cập ngắn)

```java
operation() {
    if (checkAccess()) {
        realService.operation();
    }
}
```
Proxy triển khai cùng interface với Service, thêm kiểm soát truy cập / lazy loading / logging trước khi ủy quyền cho Service thật.

#### 4.2 SOLID (5 nguyên lý OOP)

**S — Single Responsibility Principle (SRP)**
> Mỗi class chỉ có **một lý do để thay đổi**.

```java
// Vi phạm: class Person có cả logic format JSON/XML
class Person {
    String format(String type) {
        switch(type) { case "JSON": ... case "XML": ... }
    }
}
// Đúng: tách logic format ra class riêng (Formatter)
```

---

**O — Open/Closed Principle (OCP)**
> Mở để **mở rộng**, đóng để **sửa đổi**.

```java
// Vi phạm: thêm hình mới → sửa Diagram
class Diagram {
    LinkedList<Circle> circles;
    LinkedList<Rectangle> rectangles;
}

// Đúng: thêm hình mới chỉ cần tạo subclass mới
class Shape { void draw() {} }
class Rectangle extends Shape { @Override void draw() {} }
class Diagram {
    LinkedList<Shape> shapes;
    void drawAllShapes() {
        for (Shape s : shapes) s.draw(); // không cần if-else
    }
}
```

---

**L — Liskov Substitution Principle (LSP)**
> Lớp con phải **thay thế được** lớp cha mà không phá vỡ chương trình.

```java
// Vi phạm: DBConnection throws Exception rộng hơn IOException của Connection
class Connection { void connect() throws IOException {} }
class DBConnection extends Connection { void connect() throws Exception {} }
// → vi phạm LSP, Client xử lý IOException không đủ
```

---

**I — Interface Segregation Principle (ISP)**
> Client **không bị buộc** phụ thuộc vào method nó không dùng.

```
// Vi phạm: Bike bị buộc implement startEngine(), startAircon()
<<interface>> Vehicle { accelerate, brake, changeGear, startEngine, startAircon }
Bike implements Vehicle  // Bike không có engine/aircon!

// Đúng: tách thành nhiều interface nhỏ
```

---

**D — Dependency Inversion Principle (DIP)**
> Module cấp cao **không phụ thuộc** vào module cấp thấp.
> Cả hai phụ thuộc vào **abstraction**.

```java
// Vi phạm: MediaPlayer tạo trực tiếp AudioPlayer, VideoPlayer
public MediaPlayer() {
    auPlayer = new AudioPlayer();   // phụ thuộc concrete
    vidPlayer = new VideoPlayer();
}

// Đúng: phụ thuộc qua interface
<<Interface>> AudioPlayerInterface { playAu() }
<<Interface>> VideoPlayerInterface { playVid() }
// MediaPlayer chứa AudioPlayerInterface, VideoPlayerInterface
// → có thể thay implementation bất kỳ lúc nào
```

### Tóm tắt nhanh

| Mẫu/Nguyên lý | Từ khóa |
|--------------|---------|
| Composite | Cây phân cấp, interface chung, xoá instanceof |
| Decorator | Bọc wrapper, thêm hành vi động, tránh bùng nổ subclass |
| Proxy | Kiểm soát truy cập trung gian |
| SRP | 1 class, 1 trách nhiệm |
| OCP | Mở rộng không sửa |
| LSP | Con thay thế cha an toàn |
| ISP | Interface nhỏ, đúng mục đích |
| DIP | Phụ thuộc abstraction, không phụ thuộc concrete |
