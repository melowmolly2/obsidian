## What is software testing?
- Software testing is a systematic process of executing and evaluating software to: 
	- Detect defects and unexpected behavior
	- Verify compliance with specified requirements
	- Reduce the risk of failures in production
## Testing levels
- Software testing is performed at multiple levels, progressing from individual components to the complete system
	- Unit testing
		- Tests individual units or components in isolation
	- Integration testing
		- Tests interactions between combined units
	- System testing
		- Tests the entire integrated system as a whole
	- Acceptance testing
		- Validates the system from the user or business perspective
## Unit testing
- Verify the correctness of the "smallest" testable unit of software
	- Tested unit: typically a single class or individual methods
- Units are tested independantly of other components
	- Interactions with external classes or services are mocked or stubbed
- Test inputs: Method invocations with controlled parameters
- Test oracle: assertions on 
	- Returned values
	- Object state
	- Thrown exceptions
## Test case
- A test case is a well-defiend specification that describes how to verify the correct behavior of a software unit
- A test case consists of:
	- Inputs
		- Data or method calls provided to the unit under test
	- Execution conditions
		- The required system state before execution
	- Expected results (test oracle)
		- The expected output used to determine correctness
## Test activities
- Test design
	- Identify what to test and how to test it
	- Derive test cases and expected outcomes
- Test execution
	- Execute the test cases
	- Observe and interpret results
## How to desgin a test case?
- Identify the testing target
	- Determine the unit to be tested (e.g., methods, classes)
	- Analyze its specification
- Identify representative input values
- Generate test cases
## Identify representative input values
- Black-box testing techniques:
	- Focus on specifications, not implementation
		- Equivalence partitioning
		- Boundary value analysis
		- Random testing 
		- Error guessing
- White-box testing techniques
	- Focus on internal structure and code
		- Derive inputs based on the program's control flow and data flow
## Equivalence partitioning
- Partition the input space into groups of values (equivalence classes)
- Values within the same class should produce similar behavior
- Select one representative value from each for testing
## Boundary value analysis
- Focuses on testing values at the boundaries of the input ranges or equivalence classes
- Selection rules:
	- For an input in range \[min, max] test:
		- min-, min, min+
		- nominal value (nom)
		- max-,max,max+

## Combination of input parameters
- When a testing unit has multiple input parameters, and each parameter can take multiple possible values
- $\rightarrow$ How should we combine parameter values to systematically create effective test cases?
### T-way combinatorial testing
- Ensures possible combination of values of any t input parameters appears in at lease one test case
- Balances test coverage and test suite size
### What does "t-way" mean?
- Consider a method with parameters: $P_1, P_2, \cdots, P_n$ where each parameter has a set of values for testing
	- 1-way: each value of every parameter is used in at least one test case
	- 2-way(pairwise): Every possible combination of values of any two parameters appears together in at least one test case
	- 3-way: Every possible combination of values of any three parameters appears together in at least one test case
	- n-way: exhaustive testing, every possible combination of parameter values is tested
### Example 
- Given a method with three parameter:
```Java
processOrder(userType, paymentMethod, DeliveryType)
```
- Each parameter has the following test values
	- `userType: {Guest, Member}`
	- `paymentMethod: {Cash, Card}` 
	- deliveryType: {Standard, Express}
